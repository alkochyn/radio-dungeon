# radio_dungeon player

Веб-плеер для канала [@radio_dungeon](https://t.me/radio_dungeon): читает посты канала,
достаёт ссылки на bandcamp (и вообще всё, что понимает `yt-dlp`), и даёт проигрывать
треки прямо в браузере — без ручного открытия каждой ссылки.

**Слушать онлайн: [radio-dungeon.online](https://radio-dungeon.online/)** — ничего
ставить не надо. Ниже описан локальный запуск: он умеет больше (свой синк канала,
`yt-dlp` для всего, что не bandcamp), но требует установки.

Посты показываются карточками (дата, текст, треки внутри), можно лайкать посты,
раскладывать треки по своим категориям, фильтровать список и слушать вперемешку или
по кругу — всё, что заведёшь (лайки, категории), хранится только у тебя на компьютере
и не пропадёт при обновлении списка треков.

## Быстрый старт

Скачай/склонируй репозиторий, затем:

**Windows** — открой PowerShell в папке проекта и выполни:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

**macOS / Linux** — открой терминал в папке проекта и выполни:

```bash
bash setup.sh
```

Скрипт спросит, как читать канал:

1. **Без авторизации** (по умолчанию) — плеер читает публичную страницу канала
   (`t.me/s/radio_dungeon`), ту же, что открывается в браузере без Telegram. Ничего
   получать и настраивать не нужно, вход по номеру телефона не требуется.
2. **Со входом в Telegram** — то же самое плюс возможность ставить 👍 реакцией в самом
   канале от твоего имени. Понадобятся `TG_API_ID`/`TG_API_HASH` с
   [my.telegram.org/apps](https://my.telegram.org/apps) (обычный вход в свой Telegram,
   раздел "API development tools", создать приложение — название можно любое) и
   одноразовый вход по номеру телефона с кодом из приложения.

Дальше скрипт сам:

1. Проверит, что есть Python 3.10+ (и ffmpeg — он не обязателен, но с ним меньше шансов
   встретить трек, который не проигрывается).
2. Поставит зависимости в отдельное окружение (`backend/.venv`) — ничего не трогает в
   остальной системе.
3. Запустит плеер и откроет [http://localhost:8000](http://localhost:8000) в браузере.

В следующий раз для запуска не нужно повторять всё заново — просто:

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File run.ps1
```

```bash
# macOS / Linux
bash run.sh
```

Чтобы остановить плеер — `Ctrl+C` в окне терминала, где он запущен.

## Как пользоваться

- Список — карточки постов канала, внутри каждой все треки из этого поста.
- 👍 на карточке — лайк посту (ставится и в самом Telegram-канале тоже).
- «+» рядом с треком/постом — разложить по своим категориям (создаются в свёрнутой
  панели «Категории» над списком).
- Сортировка и фильтр (все / мои лайки / по категориям) над списком заодно определяют,
  что попадёт в перемешку и в переключение треков — то, что отфильтровано, не играет.
- Кнопки ⏮⏮/⏭⏭ — соседний пост, ⏮/⏭ — соседний трек, 🔀 — вперемешку, 🔁 — повтор
  (выкл / пост / трек, жать по кругу).
- ↗ рядом с датой поста — открыть исходный пост в Telegram.

### Чем режимы отличаются

|                              | Без авторизации | Со входом в Telegram |
| ---------------------------- | --------------- | -------------------- |
| Чтение постов и треков       | да              | да                    |
| Лайки, категории, фильтры    | да              | да                    |
| 👍 уходит реакцией в канал   | нет             | да                    |
| Нужен номер телефона         | нет             | да                    |
| Приватные каналы             | нет             | да                    |

В анонимном режиме лайки хранятся только в `backend/data/user_data.json` на твоём
компьютере — в шапке плеера про это висит напоминание. Переключиться можно в любой
момент: удали `backend/.env` и запусти `setup` заново, либо поправь `TG_MODE` в нём
руками (`anonymous` / `account`).

## Где что хранится

Всё личное лежит в `backend/data/` и никуда не отправляется, кроме самого Telegram:

- `tg_session.session` — сессия входа в Telegram; появляется только в режиме со входом.
- `tracks.json` — список треков, которые нашла синхронизация с каналом.
- `user_data.json` — твои лайки и категории. Синхронизация с каналом эту часть никогда
  не перезаписывает, так что обновление списка треков не сотрёт лайки/категории; на
  всякий случай перед каждой записью рядом сохраняется `user_data.json.bak`.

`.env` (там лежат `TG_API_ID`/`TG_API_HASH`) и вся папка `data/` не попадают в git — если
будешь заливать свой форк на GitHub, эти файлы туда не уйдут (см. `.gitignore`).

## Счётчик на онлайн-версии

На [radio-dungeon.online](https://radio-dungeon.online/) стоит
[GoatCounter](https://www.goatcounter.com/): он считает заходы и нажатия на кнопки —
play/пауза, переключение треков, Chaos Moon Disco, «Моя прелесть», лайки, открытие
альбома, уходы на bandcamp и в пост канала. Нужно это ровно для одного: понять, какими
частями плеера вообще пользуются.

Кук он не ставит и никаких идентификаторов не заводит — поэтому и баннера про согласие
на сайте нет. Наружу уходит только название кнопки: ни трека, ни альбома, ни поискового
запроса. Лайки и категории, как и раньше, лежат только в твоём браузере. Скрипт
подключён в конце `site/index.html`, а отправляет события `tally()` из `site/app.js`;
если его заблокировал адблок, плеер работает ровно так же — счётчику просто не
достаётся цифр.

Локальный запуск не считает ничего: счётчик есть только в `site/`, который собирается
для GitHub Pages, а `frontend/` его не подключает.

## Диагностика

- **PowerShell пишет про "execution policy" / "не удаётся загрузить файл"** — запускай
  именно как в примере выше, с `-ExecutionPolicy Bypass`, это не меняет ничего в
  системе, только разрешает выполнить конкретно этот файл.
- **Python не найден** (Windows) — если после установки Python команда всё равно не
  находится, скорее всего это заглушка Microsoft Store; поставь Python с
  [python.org](https://www.python.org/downloads/), отметив "Add to PATH", и открой новый
  терминал.
- **Порт 8000 занят** — значит плеер уже запущен в другом окне, либо порт использует
  что-то другое; останови тот процесс или измени порт в `run.ps1`/`run.sh`.
- **Ошибка "Telegram session is not authorized"** — удали
  `backend/data/tg_session.session*` и запусти `setup.ps1`/`setup.sh` заново, чтобы
  перелогиниться.

## Ограничения

- Работает только с тем, что умеет распознать `yt-dlp` (bandcamp — из коробки). Если
  исполнитель закрыл стриминг или это платный эксклюзив, трек просто не добавится при
  синхронизации.
- Анонимный режим работает только с публичными каналами, у которых не отключено
  веб-превью. Если превью выключено или канал закрытый — поможет только режим со входом.
- Разметка публичной страницы Telegram не является документированным API и теоретически
  может измениться; тогда анонимный режим придётся чинить, а режим со входом продолжит
  работать. Проверить парсер можно тестами (см. ниже).
- Первая синхронизация проходит весь канал целиком, от самого первого сообщения —
  дальше только новые с момента последнего запуска (курсор хранится в
  `backend/data/state.json`). Первая синхронизация может занять
  до 20 минут: каждая ссылка отдельно прогоняется через `yt-dlp`. Синхронизация запускается
  сама при каждом старте плеера.

## Тесты

Сеть не нужна: оба файла поднимают локальный сервер, отдающий разметку в формате
`t.me/s/`, и подменяют `yt-dlp` заглушкой.

```bash
cd backend
.venv/bin/python tests/test_web_sync.py        # парсер и постраничный обход
.venv/bin/python tests/test_anonymous_mode.py  # запуск, синхронизация, лайки, режимы
```

На Windows вместо `.venv/bin/python` — `.venv\Scripts\python.exe`.
